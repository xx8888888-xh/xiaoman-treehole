## 2. 发现并修掉的 CI 环境问题

| 问题 | 现象 | 修法 |
|---|---|---|
| BuildKit 特权构建 | `docker compose build` 报 `additional privileges requested: pass "--allow=network.host"` | 新增 `.github/ci/docker-compose.ci.yml` 把三服务 `build.network` 覆盖为 `default`；`COMPOSE_FILE` 注入 |
| Android SDK 包消失 | `android-actions/setup-android@v3` 调 `sdkmanager tools`，cmdline-tools 16 已无该包 | 去掉该 action，直接用 runner 自带 SDK + 动态 `find sdkmanager`，安装 platform-34/build-tools/34.0.0 |
| 旧 workflow 抢跑 | `quick.yml`、`healthcheck.yml` 每次 push 都跑 | 删除；`android-ci.yml` 改为仅 manual |
| 浏览器 CPU 打满 | 本地 `chrome-headless-shell.exe` 曾占 75% CPU | `scripts/browser_guard.py` + 13 个 Playwright 脚本接入；本地默认退出码 2 |
| 闸门误判云端 | 本机终端全局 `CI=true`，用它当云端判据形同虚设 | 改用 `GITHUB_ACTIONS=true`（或 `XIAOMAN_ALLOW_LOCAL_BROWSER=1`） |
| e2e 迷你窗假红 | 4 条 workflow 并发时 `⑦l-2` 取到 4 个字符就断言（`tail='满失眠这'`） | 等文本连续两次采样不变再断言，阈值 `>4` 字**不变** |
| Playwright 重复下载 | 每次 e2e 重装 Chromium | `actions/cache@v4` 缓存 `~/.cache/ms-playwright`，key 绑定 `PLAYWRIGHT_VERSION` |

## 3. 浏览器硬闸门与本地资源约束

- 放行条件：`GITHUB_ACTIONS=true`（云端自动）或 `XIAOMAN_ALLOW_LOCAL_BROWSER=1`（本地显式 opt-in）；被拦退出码 2 = "未执行"。
- 已接入 13 个脚本：`test_e2e` / `test_feature_loop` / `test_live2d_original` / `test_raf_budget` / `test_appearance` / `test_lifeline_ui` / `test_onboarding` / `test_paging` / `test_phase3_e2e` / `test_stream_e2e` / `ui_tour` / `ux_walkthrough` / `shot.py`。
- 本地跑完必须显式退出（异常中断才可能残留）：

```powershell
Get-Process chrome-headless-shell,chrome -ErrorAction SilentlyContinue
Get-Process chrome-headless-shell,chrome -ErrorAction SilentlyContinue | Stop-Process -Force
```

- 单会话本地占用上限 30%–40%：本轮只做 git / gh / GitHub API 上传，无 headless 渲染、无 AVD、无 Gradle。
  实测本会话 `python` 进程累计 CPU < 5s（占单核 <1%）；整机内存占用 42.7%（含其他应用，非本会话独有）。
