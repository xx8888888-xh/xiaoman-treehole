# 小满人格变更流程（P0-3 关系连续性承诺）

> **背景**：Replika 2023 年单方面修改关系设定，用户一觉醒来"认识的那个人"变了，社区暴动、大量用户流失。教训不是"不能变"，而是**不能背着用户变**。
> 小满的承诺：人格层的每次变更，用户**看得见、查得到、能反馈**。
> 验收口径出处：docs/PRODUCT_ROADMAP.md P0-3；测试：test_memory_recall.py G6（13 点）+ test_e2e.py ⑦d（3 点）。

---

## 一、什么算"人格层变更"

| 变更类型 | 算不算 | 说明 |
|---|---|---|
| 模板话术（TOPIC/GREET/HOOKS/CARE_SCRIPT 等正文改动） | **算** | 用户直接感知"说话的味儿" |
| 记忆逻辑（提取正则、回提闸门、守卫规则） | **算** | 影响"它记不记得我"的体感 |
| 情绪/动作映射（EMO_MAP/MOTION） | **算** | 表情联动是人格的一部分 |
| 纯 bug 修复（行为不变，如端口、崩溃、语法） | 不算 | 用户无感 |
| 基础设施（CI、构建脚本、依赖升级） | 不算 | 不触及人格层 |

拿不准就登记——多告知一次的成本远低于"用户觉得它变了却没人解释"。

## 二、三步流程（每次人格层变更必须走完）

### 第 1 步：登记（变更提交前）

三端**同源登记**，新条目插数组头部，`XIAOMAN_VERSION` 递增：

| 端 | 位置 | 登记内容 |
|---|---|---|
| 服务端 | `server/mock_api.py` → `XIAOMAN_UPDATES` + `XIAOMAN_VERSION` | `(日期, 用户向一句话)` |
| 离线引擎 | `web/js/mock_engine.js` → `XIAOMAN_UPDATES` + `XIAOMAN_VERSION` | 同上（**逐字同源**） |
| 前端 | `web/js/app.js` → `XIAOMAN_VERSION` + `UPDATE_TELL` 文案 | 版本号与告知文案同步 |

`note` 写**用户能懂的话**（"学会了记事"），不写代码术语（"新增 MEM_PATTERNS 正则"）。

### 第 2 步：告知（自动，无需人工）

- **老用户**（已有任一记忆）：人格变更后**首次再访**，greet 时段问候后自动追加 `UPDATE_TELL`（"我这两天悄悄升级了一下脑子……你要是觉得我哪不对劲、不像以前了，直接告诉我，我听"），**一次即登记**（幂等）。
- **新用户**：静默登记版本，不告知——没有"以前"可对比，首面就说"我升级了"反而诡异。
- 幂等键：服务端 session 状态 `told_v`；前端 localStorage `xiaoman_told_v`；离线引擎以历史消息是否出现过告知文案代判定（刷新即重置，可接受——离线场景历史也在内存）。

### 第 3 步：可查（用户随时问）

触发词（`update_query` 正则，三端同源）：
- "你最近**更新**了什么 / **升级**了吗 / 你**变了** / 不像以前了 / 你今天有点**怪**……"
- 播报**最近 3 条**更新（日期转口语："11号学会了主动汇报……"），并以"要是觉得我哪里变了不像以前，尽管说，我改"收尾，把反馈邀请递出去。
- 主语收紧防误伤：`你(?!们)`——"你们老板更新了周报模板"不触发；"你变漂亮了/你变得开心了"不触发（触发词要求"变了"整体或"怪/版本/更新/升级"）。
- 优先级：**危机 > 元问题 > 更新查询 > 话题池**（危机句里含更新词仍走危机线，G6-3① 验证）。

## 三、版本登记表（与代码同步维护）

| 版本 | 日期 | 变更（用户向） |
|---|---|---|
| v2 | 2026-10-11 | 学会了主动汇报——就现在这样，你一问我就能答 |
| v1 | 2026-10-10 | 学会了记事——你跟我说的大事、宠物名字、老板叫啥，我都记着 |

> 改人格层时**此表必须同步更新**，否则文档与代码漂移。

## 四、用户反馈回路

`UPDATE_TELL` / 播报收尾都显式邀请反馈（"直接告诉我，我改"）。
当前：反馈落入对话自然流，人工消化后进入下一轮迭代。
后续候选（未立项）：加"反馈"记忆键自动收集。

## 五、"灰度"的本地对应物

本应用为本地单用户部署，无服务器灰度。等效保障：

1. **告知一次性**——升级信息不刷屏（幂等登记）；
2. **变更日志用户可见**——`update_query` 随时可查（对应"变更日志对用户可见"的验收口径）；
3. **回退路径**——git revert 到旧版本即回退人格。
   边界行为：版本号回退后 `told_v > XIAOMAN_VERSION`，不再重复告知（静默回退，不崩不闹）；用户问更新记录能查到回退后版本的内容。

## 六、变更检查单（提交前过一遍）

- [ ] 三端 `XIAOMAN_VERSION` 一致且已递增？
- [ ] `XIAOMAN_UPDATES` 两端逐字同源、新条目在头部？
- [ ] note 是用户向语言，不是代码术语？
- [ ] `docs/PERSONA_CHANGE_PROCESS.md` 登记表已同步？
- [ ] G6（13 点）+ ⑦d（3 点）全绿？
- [ ] 全套回归无退化？
